# Repository Guidelines

## プロジェクト構成とモジュール整理

このリポジトリは Neovim の Lua 設定です。エントリポイントは `init.lua` で、共通設定は `lua/core/`、プラグイン定義は `lua/plugins/`、見た目や個別設定は `lua/user/` にまとまっています。ロックファイルは `lazy-lock.json`、静的解析の設定は `selene.toml` と `neovim.yml` にあります。テストやアセット用のディレクトリは現状ありません。

## ビルド・テスト・開発コマンド

ビルドは不要です。普段の動作確認は Neovim を起動して行います。
- `nvim`：設定を読み込んで起動します。
- `:Lazy sync`：`lazy.nvim` でプラグインを同期します。
- `selene lua`：Lua の静的解析を実行します（Selene が導入済みの場合）。

## コーディングスタイルと命名規則

Lua は 2 スペースのインデントを推奨します。モジュールは `lua/` 配下に置き、`core`, `plugins`, `user` の階層を守ってください。ファイル名は snake_case で、プラグイン設定は 1 ファイル 1 プラグインにするのが基本です。`selene.toml` のルールに従い、未使用変数や未定義変数は警告扱いです。

## テスト方針

自動テストは用意されていません。変更後は `nvim` の起動確認と、対象機能の手動チェックを実施してください。必要に応じて `:checkhealth` や関連プラグインのヘルプを参照します。

## コミットとプルリクエスト

Git 履歴の規約は未確認のため、簡潔で目的が分かるメッセージを推奨します（例: `feat: add LSP keymaps`）。PR には変更概要、動作確認内容、必要であればスクリーンショットを含めてください。関連 Issue がある場合はリンクを記載します。

## 追加の注意点

`lazy-lock.json` は依存を固定するため、プラグイン追加や更新時に差分が出るのは正常です。`init.lua` の `lazy.nvim` ブートストラップ部分は変更が必要な場合のみ編集してください。
